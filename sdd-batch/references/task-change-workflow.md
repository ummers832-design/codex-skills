# 按需求定位任务、检查边界并修改文件

适用于用户提出新增、删除、调整或修复，希望修改 PRD 已拆分的任务点及其 SDD 的场景。用户的修改描述是定位和变更依据，不自动证明该变化已在原始范围内。

## 1. 找到真实依据与对应任务

先读取实际项目中的原始 PRD 版本及确认状态、技术 PRD、功能拆分、已确认变更、任务文件与相关批次 SDD。沿用已有路径和编号，不要求用户重新拆任务，不将固定 PRD 当作可改工作文件。

按业务含义检索，而非只匹配标题：从用户描述提取对象、动作、输入输出、规则、权限和验收变化。优先按需求／技术／功能／批次编号映射，再核对文件正文、依赖和验收条件。

记录对应关系：`用户变化 → 原始 PRD 章节／需求编号 → 已确认变更（如有）→ 功能编号 → 任务编号与文件章节 → 批次 SDD → 受影响验收`。

- 一个变化涉及多个任务时，列出主任务和依赖任务，分别修改实际受影响部分，不只改第一个命中结果。
- 任务在汇总文件中时直接修改该任务章节；已有独立文件时修改对应文件。不强制迁移成一任务一文件，不重复新建同义任务。
- 有多个候选且不能区分时，说明候选与差异，请用户澄清；可继续无歧义部分，不能随机选一个改。
- 未找到任务不等于超出 PRD。若原始 PRD 明确包含但拆分遗漏，标明遗漏并补充映射和任务；若原始 PRD 不包含，按边界规则处理。
- 原始基线或确认版本缺失时，只做定位和修改提案，结论写“无法判定边界”，不把草稿当已批准范围。

## 2. 修改前判断边界

每个变更点分别对照原始 PRD 的目标、本期范围、非目标、业务规则、权限、数据、输入输出、外部依赖、验收及非功能约束。同时核对已确认变更构成的当前有效范围，但必须保留与原始 PRD 的差异，不能用新任务把越界事实掩盖掉。

| 分类 | 判断 | 处理 |
|---|---|---|
| 原始范围内 | 原文或可定位规则支持；修复偏离既定行为，或不改变交付能力的实现调整 | 按当前用户授权直接修改对应任务与必要 SDD，不重复索要范围批准 |
| 超原始范围，已有明确批准 | 原文不含或被排除，但实际确认记录明确纳入当前有效范围 | 仍提醒“超原始范围，已由某条变更纳入”，引用依据后修改；不重复询问已有批准 |
| 超原始范围，未确认扩展 | 新模块、新交付、新外部对接、改变业务／权限边界，或提升已定容量、效果、性能等承诺 | 先提醒具体差异与影响，给出任务修改提案；未有明确纳入决定，不覆盖生效任务与 SDD |
| 边界不明 | 原文含糊、相互冲突、无固定基线或确认权限不清 | 列出缺失依据和需要决定的事项；保留原有效任务，准备候选修订 |

“加一个字段”也可能改变核心业务；“改很多代码”也可能只恢复原约定。不能用文件数量、代码行数、按钮数或主观工期代替范围判断。需求减少、删除、延期和替换也需要检查承诺和依赖，不只检查新增。

“请修改”授权进行本次文档工作，但不自动等于批准所有未提示的范围扩展。先将越界内容说明清楚；用户已明确表示“将该项纳入本期并更新对应任务”等，则记录其实际决定，不再次确认。不能伪造其他决策人的授权或外部批准。

## 3. 修改对应文件内容

在允许修改的范围内，直接编辑任务的目标、范围、规则、输入输出、依赖、验收和实现／验证子任务，并同步受影响 SDD 的数据模型、接口、权限、状态、迁移和风险；不只追加一段备注而留下矛盾旧规则。

保持未受影响内容、稳定任务编号和引用。已完成任务的历史与验收证据不改成新功能已经完成：在原任务记录后续变更关联，将新增工作标为待实现／待验证；项目规定已归档任务不可改时建立关联的后续任务。确认过的规格在实质修改后注明本次变更待相关开发人员复核，不沿用旧确认声称新规格已确认。

固定 PRD 保持原文；已固定或归档的 SDD 按项目版本规则另建修订版或后续变更规格。普通可编辑任务与 SDD 直接原位修订。记录实际变更依据和差异，不擅自修改客户确认记录。

混合请求按变更点拆开：先完成明确范围内且不依赖未决扩展的部分；越界或不明部分留为单独提案，不因为局部问题停止全部工作，也不让依赖未决扩展的任务先行生效。

只有新的、已确认范围在既有任务中无合理归属时才补任务。默认修改文档不代表执行代码、数据库迁移或创建外部任务，除非用户另有授权。

## 4. 校验与返回

检查任务与 SDD 是否一致、引用是否有效、删除后依赖是否悬空、权限与数据规则有无冲突，以及验收是否覆盖新旧受影响行为。按变更影响检查，不把结构检查等同于实现验证。

返回：匹配到的任务及文件、与原始 PRD 的边界结论及实际依据、已修改内容、受影响的其他任务／批次、未决事项和检查结果。有越界时显著说明：

> 超出原始 PRD 范围：原约定为……；本次希望……；涉及……任务及交付／依赖变化。当前状态：已确认扩展／待确认扩展。已完成……；尚未将……写入生效规格。

没有修改成功不称已保存；没有实施和测试不称功能已完成。新增边界结论可记录在项目已有变更记录，不为每次小修机械创建整套文件。
