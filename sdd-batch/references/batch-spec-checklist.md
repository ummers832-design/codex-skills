# 本批 OpenSpec 规格确认清单

> 在你回复"可以，开始开发"前，对照本清单。**未解决且影响本批实现的问题先澄清**。

## A. 需求范围

- [ ] A1. 本批需求覆盖完整
- [ ] A2. **范围**与**非目标**清楚
- [ ] A3. 需求依据可定位（指明 PRD / SOW / 变更记录编号 / 会议纪要）
- [ ] A4. 已读取**固定详细 PRD**、**内部 SOW**、**已确认需求变化**
- [ ] A5. 已确认本批属于哪个类别：业务变更 / 数据结构 / 权限 / 公共能力 / 性能·安全·合规 / 数据迁移

## B. 数据库

- [ ] B1. AI 提供的**设计变更摘要**已阅读：新增表 / 修改字段 / 原因 / 功能影响
- [ ] B2. 详细设计已检查（字段、类型、约束、索引、迁移方案）
- [ ] B3. 数据字段与**实体关系**正确
- [ ] B4. 字段类型、约束等满足本批业务（含必填、默认值、唯一性、长度、枚举）
- [ ] B5. 涉及迁移时，AI 已标记：删除数据 / 字段改名 / 类型变化 / 历史数据转换
- [ ] B6. 上述风险已 review；判断不准的问题已寻求有经验人员协助
- [ ] B7. 迁移已**确认分批规模门限**：≤ 1 人周、≤ 3 新表、≤ 5 新接口

## C. 接口

- [ ] C1. 接口能支撑页面字段及操作
- [ ] C2. **可读姓名**等数据来源已明确（不直接用内部 ID 替代）
- [ ] C3. 完整请求与响应字段、校验、错误码已定义
- [ ] C4. 分页、幂等等适用约定已明确
- [ ] C5. **第三方接口的可用性和限制**已确认（签约前已查清，不留到开发）
- [ ] C6. 触发 **SOW 上浮**的条款已全部回 FDE（第三方限制 / 核心实体 / 报价 / 合规 / 跨系统数据归属）

## D. 权限与数据归属

- [ ] D1. **权限**（谁能做什么）明确
- [ ] D2. **数据归属**（属于谁、谁能看）明确
- [ ] D3. **异常反馈**（失败、超时、权限拒绝）明确
- [ ] D4. 未分配 / 数据缺失 / 尚未加载 / 真实零值 这几种状态已区分，不混用

## E. 公共能力与依赖

- [ ] E1. **公共能力**（登录 / 权限 / 文件存储 / 消息）已识别，未在本批重复造
- [ ] E2. **前置依赖**（跨服务、跨团队）已检查
- [ ] E3. 对**其他模块的影响**已列出（影响范围 + 验证范围）
- [ ] E4. **跨批次依赖**已标明（让下一批能接续）

## F. 验收

- [ ] F1. 验收条件能用于检验实际结果（非"看起来对"）
- [ ] F2. OpenSpec 任务覆盖**实现 + 验证**两端
- [ ] F3. 验证方式明确：单测 / 集成 / E2E / 影子流量 / 性能 / 混沌（按影响选）
- [ ] F4. 监控指标与报警阈值（如涉及）已定义
- [ ] F5. **每条"完成"声明都有 §5 证据类型对应**（测试报告 / 截图 / 压测 / 抽样对账 / 回滚演练 / 接口样例）

## G. 风险与回滚

- [ ] G1. 已知风险已列出
- [ ] G2. 缓解措施（开关、降级、限流、灰度）明确
- [ ] G3. **回滚方案**可执行（不是"出问题再说"）
- [ ] G4. 灰度 / 切流策略（如涉及）已明确
- [ ] G5. **回滚已实际演练**（staging 环境 upgrade + downgrade 实跑记录），不只是"理论上能回"

## H. 角色确认

- [ ] H1. 负责人 / FDE 已安排任务（需求依据、范围、验收、负责人、完成时间）
- [ ] H2. **本批规格已由承担任务的开发人员本人确认**
- [ ] H3. 跨团队 / 跨 FDE 沟通已完成（无悬空问题）

## 收尾

- [ ] 全部打勾 → 可回复"确认，开始开发"
- [ ] 任意一项未打勾 → 列出未解决项，**先澄清再开发**
- [ ] SOW 上浮触发 → 停下，回归 FDE；不要"边做边聊"
