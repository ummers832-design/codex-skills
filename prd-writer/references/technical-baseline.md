# 默认技术框架与工程约束

技术 PRD 默认采用以下开发基线，不将其全部留成“尚未选型”。使用通用表述，不在生成文档中说明机构身份或内部规范来源。已有项目的明确技术约定与本基线不一致时，列出差异并沿用实际确认结果；需要偏离时说明原因、影响和替代方案，交技术方案负责人确认，已有批准不重复索取。

## 框架与部署

| 层次 | 默认基线 | 项目中需明确 |
|---|---|---|
| 前端 | React + Vite + Mantine；无 SEO 要求的内部系统采用 SPA | 实际使用端与 SEO 要求、依赖版本、设计约束 |
| 前端部署 | 静态产物部署阿里云 OSS，浏览器产物不含密钥 | Bucket、域名与访问方式；SEO 场景另明确渲染和部署方案 |
| 业务后端 | Python 3.12 + FastAPI，业务 API 收口后端 | 模块边界、鉴权、数据读写与外部服务交互 |
| 后端部署 | 阿里云函数计算；轻依赖优先自定义运行时代码包，系统二进制、本地模型或打包限制需要时采用镜像 | 实际依赖、启动入口、资源限制和部署方式，以验证结果为准 |
| 数据库 | 阿里云 RDS，数据库引擎按项目选择；Alembic 管理迁移 | 引擎及版本、核心实体、数据归属与容量；不默认全部项目用 MySQL 或 PostgreSQL |
| 文件存储 | 阿里云 OSS | 文件来源、访问权限、存储与处理覆盖；不等于自动授权上传现有资料 |
| AI Agent | 阿里云 AgentRun，以代码模式为主 | 实际是否涉及 Agent、AgentRun 与业务后端衔接；不预设统一 Agent SDK 或模型厂商 |
| 源码与发布 | Codeup；合并前检查由 AI 在开发环境运行，开发人员 review；发布使用流水线 | 实际仓库、分支、发布与放行配置；不默认已创建资源 |

SEO 不自动意味着换前端框架或必须常驻服务器；预生成的静态 HTML 仍可部署 OSS。代码包与镜像不能宣称无需修改即可互换。已有前端 Mock 模板不代表完整生产脚手架已经具备。

## 系统职责与环境隔离

普通业务路径：浏览器 → React 前端 → FastAPI → RDS／OSS／外部服务。浏览器不直连数据库，业务鉴权与 SQL 收口后端；AgentRun 按实际架构衔接，不重复建设两套业务后端，也不以单一入口否定明确采用的 Agent 服务。

生产资源使用指定的阿里云账号。dev、uat、生产分别部署独立函数；OSS 按项目及环境使用独立 Bucket；项目与环境各自使用独立数据库账号，仅访问自己的库。不同项目可共用 RDS 实例但分别建库，不能据此共用数据库账号。库名通常采用 `<项目>_dev`、`<项目>_uat`、`<项目>_pro`，实际资源映射在技术 PRD 或部署方案中记录。

这是资源组织约束，不代表客户已授权上传原件、已确认云处理、费用已包含或项目可无条件共用实例。项目数据约束冲突时提出方案偏离和待决事项。

## 数据迁移与安全约束

- Alembic 迁移需有变更摘要、已有数据影响与恢复方案，开发人员 review；先在 dev 验证数据保留及相关业务，再使用同一套版本化迁移文件推进至 uat 和生产，不分别重新生成。
- 删除、改名、类型变化及历史数据转换须标明风险；降级脚本不等于能恢复已删除数据。生产执行遵循实际放行流程，不默认新增审批或强制迁移接入流水线。
- Git 文件、浏览器产物及接口响应不得包含真实密钥；环境模板使用占位符。数据库及外部服务连接使用 TLS 并校验证书。
- 鉴权接入实际路由，写操作检查身份和角色；内网不替代鉴权。公开接口的例外需有明确依据。
- 检查按实际变更影响执行，不因技术 PRD 罗列约束而对无关小改动全量重复检查。

## 写入与交接

技术 PRD 必须有“默认技术框架与项目适配”章节，逐层说明采用基线、实际约束、未决选项与偏离。模型、OCR、检索产品、任务队列和监控产品未在此基线中统一指定，不擅自补成已选型；仅在需求适用时评估。

功能拆分继承相关技术约束，各批 SDD 再定义完整表字段、接口、运行配置、迁移及验证步骤。不把技术框架默认值当作客户业务范围确认、服务能力证明或实际部署完成。
